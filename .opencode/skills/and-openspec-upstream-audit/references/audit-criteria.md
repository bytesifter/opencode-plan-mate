# audit-openspec 四维审计判定标准

本文件是 audit-openspec skill 的判定权威源，L2/L3 判断以此为据。

**判定标准全部在审计执行时经项目根 `AGENTS.md` 定位规范后抽取**：细化链的层数、各层定义、各层文档落点、缺位规则均以运行时读到的适用规范为准。本文件只含抽取方法论、四维判定框架、红线框架与报告口径，**不含任何写死的层名、文档路径或关键字**。

## 适用范围

- 面向**新生成的 openspec change**，change 生成后由用户**手动执行**审计
- **存量 change 不审计、不回填上游引用**；新规范从新 change 生效
- 细化链适用于**程序项目**；配置/文档项目（无对应上游层）按「声明缺位但已说明」处理：proposal 已显式标注「该层不存在」即不判硬性缺失
- **只读不自动修**：审计只报告问题与修复方向，不自动改 change 或上游文档

## 细化链抽取（Step 0）

从适用规范文本抽取细化链模型，每条必引「规范依据（文件 + 条款）」：

- **层清单**：每层 `id` / `label` / 文档落点模式 `patterns`
- **层间顺序**：上层回答「为什么 / 怎么做对」，下层回答「怎么实现 / 改了什么」；每层须比上层更具体
- **必须性**：哪些层对哪类 change 为必须层；常规修正（bugfix 等）的例外
- **缺位规则**：允许显式标注「该层不存在」的场景与表述

抽取冲突或空缺（同一层落点说法不一、某层无落点定义）时 **Step 0 门禁中断**，只输出规范问题清单，不审计 change。

## 四维判定标准

| 维度 | 检查内容 | 判定 | 检查层 |
|------|----------|------|--------|
| 存在性 | 抽取细化链中的各上游层是否都有对应；缺失是否显式声明 | 通过=各层有对应；声明缺位但已说明=proposal 标注「该层不存在」；缺失=无对应且未声明 | L1 + L2 |
| 清晰度 | 每层是否比上层更具体（非重复 / 非模糊） | 通过=逐层更具体；部分=某层与上层等粒度；缺失=某层重复或模糊 | L2 |
| 粒度 | 细化粒度是否递增、无跳级 | 通过=递增无跳级；缺失=跳级 | L2 |
| 偏差 | change 是否超出 / 冲突上游设计 | 通过=不越界不冲突；偏差=change 改了上游未说过的（越界），或上游说了 change 未对齐的（未对齐） | L3 |

## 红线框架（命中任一即判偏差，需人决策修复方向）

- **凭空产生**：proposal 完全无上游引用（存在性缺失）
- **越界**：change 引入上游未设计的行为 / 能力（上游未声明，change 新增）
- **未对齐**：change 移除 / 遗漏上游仍声明的能力
- **必须层缺失**：对某类 change 为必须的上游层缺失，且未声明缺位（具体为哪层以抽取的规范规则为准）

## 实现说明

- L1 可机械查的（上游锚点存在性、缺失层声明）由 `lint.py` 检测，层定义经 `--layers` 传入（运行时抽取）；缺失未声明 severity 设 error，声明缺位设 warning
- L2 需 AI 判断的（存在性核对、清晰度、粒度）由 SKILL.md Step 2 判断，输出 通过/部分/缺失 + 依据
- L3 需 AI 对照上游的（越界/未对齐）由 SKILL.md Step 3 判断，逐条列出变更点 vs 上游位置
- 任一红线命中，报告「红线」段列出，修复方向由人决策（补引用 / 补上游 / 更新文档）
