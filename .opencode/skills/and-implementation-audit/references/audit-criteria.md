# audit-implementation 判定权威源

本文件是 audit-implementation skill 的判定权威源，Step 1-4 以此为据。涵盖：四类声明源运行时抽取（`openspec/config.yaml` 为第一声明源）、双向对照与四态判定（自洽/空头设计/无依据/跑偏）、代码风格规则可机检对照、审计边界（不审代码质量）、只读报告口径（按声明源分组，保留规范语气）、手动触发与作用域边界。**判定标准全部在审计执行时从声明源文本抽取**，本文件只含抽取方法论、门禁判定、双向对照框架、四态判定与报告口径，**不含任何写死的声明类型或路径**——声明类型、位置、内容一律以运行时读到的声明源为准。

## 适用范围

- 面向**程序项目**实现侧，由用户**手动触发**（输入项目根目录）
- 判定为 **AI 语义判断 + 可机检规则确定性验证**；skill **不发明规范、不裁决声明冲突**
- **只读不自动修**：审计只报告，不自动改代码或声明
- 不审计 openspec change 的 diff 落地（openspec 流程职责）、不审计设计文档体系（audit-design-system 职责）、不校验技术文章（validate-article 职责）

## 四类声明源抽取方法论

| 源 | 识别方式 | 声明依据要求 |
|----|---------|-------------|
| ① openspec | 读 `openspec/config.yaml` 的 `context` 目录结构（顶层职责/放置规则/禁止区），为**第一声明源**；可选读 change 产物声明 | 必引文件+位置 |
| ② 规范 | 读运行时定位的适用语言规范的命名/格式化/注释/常量表格规则 | 必引条款 |
| ③ 架构 | 读运行时定位的架构类文档的模块划分/技术选型/数据模型/部署/安全/集成声明 | 必引文档+章节 |
| ④ 技术方案 | 读运行时定位的技术方案类文档的包名规范/实现决策 | 必引文档+章节 |

- **源缺失缺位处理**：某类声明源不存在（如无技术方案文档）→ 按「该层不存在」声明缺位，不误报存在性缺失
- 每条抽取必引「声明源文件+位置」，供人工覆核
- 抽取时对 config.yaml 与架构文档对同一实体的说法做交叉比对

## 门禁判定标准

Step 1 抽取时命中任一即中断，输出「声明冲突清单」，不审计代码：

| 类型 | 判定 | 行为 |
|------|------|------|
| 冲突 | config.yaml 与架构文档对同一实体说法不一致（如模块数说法不一） | 中断，输出双方声明位置与事实，不审计代码、不提修复方案 |
| 空缺 | 代码出现实体但四类声明源均无对应声明线索，无法判定是声明缺失还是设计缺位 | 中断，同上 |

## 双向对照与四态判定框架

| 方向 | 检查内容 | 判定 |
|------|---------|------|
| 声明 → 代码（覆盖） | 声明是否有对应实现 | 有=进入一致检查；无=**空头设计** |
| 代码 → 声明（依据） | 实现是否有对应声明 | 有且一致=**自洽**；有但冲突=**跑偏**；无=**无依据** |
| config.yaml 对照 | 代码实体是否有 config.yaml context 声明的目录/包名对应 | 有=有依据；无=**无依据**；声明粒度不足=标注「声明粒度不足，需人工确认」 |

具体判定内容**全部来自运行时抽取的声明/规则清单**，本表只是通用框架，不预设任何声明类型或路径。

## 可机检规则与语义规则

- **机检规则**（正则/工具可验证）：命名规则（camelCase/PascalCase/snake_case 等）、行宽、格式化工具（gofmt/black/prettier）、常量命名（UPPER_SNAKE_CASE）——确定性验证
- **语义规则**（AI 判断）：职责分离、模块边界、实现决策合理性——语义判断
- 无声明条款约束的结构问题（代码质量层面）不判不合规

## 报告口径

**审计报告**（门禁通过时）：按声明源分组，每条 finding = `声明源 / 声明位置 / 判定态(自洽/空头设计/无依据/跑偏) / 现状 / 基于声明的修改方向`。给依据而非纯判定，允许人工覆核。

**修改方向语气**：保留声明自身的强制语气——规范标 [必须] 写「按 §x 必须…」，标 [推荐] 才可写「按 §x 建议…」；未规定改法时引声明原文，不发明。报告**不引入严重度/优先级分级，不发明规范未给出的豁免**。

**声明中断报告**（门禁命中时）：仅 `类型(冲突/空缺) / 涉及实体 / 声明位置(文件+位置) / 事实`，不输出修复方案。

## 实现说明

- 全流程 AI 判定 + 确定性辅助（目录树/依赖清单/格式化工具运行结果），辅助手段不写死类型
- 任一抽取结果必引声明源位置（文件+位置），供人工覆核
- 门禁中断是设计意图（声明自洽是审计前提），非缺陷
