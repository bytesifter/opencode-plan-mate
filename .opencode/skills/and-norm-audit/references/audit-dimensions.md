# audit-norms 八维度判定细则

本文件是 `audit-norms` skill 的判定权威源。判定依据为规范体系既有元规则（`AGENTS.md` §六 与适用规范相应条款），不得发明规范外标准。每维度标注**类型**（确定性=脚本可判定；语义=AI 判定）。本 skill 的审计对象即规范体系本身，故对元规则与规范体系自带工具（如一致性校验脚本）的引用属**域内固有依赖**，非硬编码外部规范名；其余可运行时定位的规范文件一律泛引用，不写死具体文件名。

## ① 归属与加载（确定性 + 语义）

**依据**：`AGENTS.md` §二（层归属表）+ §六.1「层归属单一权威」+ 项目类型 → 层的加载规则（见 `AGENTS.md` §二及各加载规范）。

**检查项**：
- 确定性：`AGENTS.md` 层归属表是唯一成员来源；各加载规范只表达「类型 → 层」，不复制文件清单；其余相关规范为指针
- 语义：文件声明的层与路由表 / 加载表 / 各文件「不加载」列表是否一致；是否存在同一文件被归入不同层

**判定**：层清单出现两处及以上不一致 → 不合规，引 §六.1 层归属条款。

## ② 交叉引用（确定性 + 语义）

**依据**：目标存在 / 章节锚 → `AGENTS.md` §六.4「引用格式」；单向 / 成环 → `AGENTS.md` §六.7「主题单一权威」（按规则依赖判定）；可达 → 审计方法的**通用项**（规范正文无对应元规则）。

**检查项**：
- 确定性（§六.4）：引用的 `./AGENTS-x.md`（或 `../AGENTS.md` 主索引、`./norms/AGENTS-x.md` 等）**按路由表解析规范文件所在目录后**判断目标是否存在；章节引用是否带编号锚点 `§x.y`（不得只写「§章节名」）
- 语义·§六.7（单向、无环）：
  - 引用是否单向（权威文件不得反向指向下层以补自身核心规则）
  - 引用关系是否成环——仅当**同一主题的双向规则依赖**（A 的规则依赖 B，且 B 的规则依赖 A）时判为环；主题互指、前置依赖、信息性交叉引用不判为环
  - 判定问句：这两条边是否在支撑**同一条规则**的权威？是 → 环；否 → 非环
- 语义·通用项（可达）：
  - 引用目标是否可达（不指向引用方所属项目类型不加载的文件 = 死引用）

**判定**：目标存在 / 章节锚（§六.4）由脚本判定，命中 → 不合规；单向 / 成环（§六.7）由 AI 按上口径判定，命中 → 不合规；可达（通用项）由 AI 判定，命中报告为**通用项**，不表述为「不合规」。

## ③ 边界与重复（语义）

**依据**：`AGENTS.md` §六.7「主题单一权威」+ §六.10「引用化原则」。

**检查项**：
- 同一主题的规则正文是否只存在于唯一权威文件；其他文件是否复述
- 权威文件之间是否就同一主题给出强度不一的重复规则
- 父子 / 专项规范之间是否存在并列冲突
- 规范正文是否以复述形式承载开源 / 官方标准已有内容（未引用权威源、未收窄为团队增量）

**判定**：同主题多处定义 → 不合规，引「主题单一权威」；复述开源 / 官方标准 → 不合规，引「引用化原则」。

## ④ 内部一致性（语义）

**依据**：审计方法的**通用项**（规范正文无对应元规则）；判定口径=文件内前后不自相矛盾。

**检查项**：
- 文件内是否有自相矛盾的表述（如同一事项两处说法不一）
- 术语是否通篇一致（同一概念不多名）
- 章节号是否连续（子节号与章序号对应）

**判定**：命中 → 不合规，给「文件:行」定位与两处原文。

## ⑤ 可执行性 / 正确性（语义）

**依据**：`AGENTS.md` §六.6「规范事实纪律」。

**检查项**：
- 规则能否被执行（有无不可判定 / 空洞表述）
- 规则会否误伤或漏判（护栏是否过宽 / 过窄）
- 事实纪律：是否存在无出处、未标「未验证」的外部事实断言
- 环境相关示例是否标注平台

**判定**：命中 → 不合规，引「规范事实纪律」。

## ⑥ 元数据（确定性）

**依据**：`AGENTS.md` §六.2「元数据标准」。

**检查项**：
- 每个 `AGENTS-*.md` 文末是否有且仅有一处「最后更新」（YYYY-MM-DD）与「版本」（x.y）
- 元数据块是否有重复行

**判定**：缺失 / 重复 → 不合规，确定性脚本判定。

## ⑦ 语言政策（确定性）

**依据**：语言政策规范正文；`AGENTS.md` §六.3「模态标记统一」。

**检查项**：
- 中英夹杂（有干净中文对应却用英文的强调词，如 CRITICAL / IMPORTANT / WARNING）
- 模态标记是否符合 `AGENTS.md` §六.3（当前三档 `[必须]`/`[禁止]`/`[推荐]`）；是否存在用加粗承担模态

**判定**：命中 → 不合规，确定性脚本判定（词表 + 加粗模态正则 #11 / SHALL·MUST #14）。

## ⑧ 时效性（语义）

**依据**：审计方法的**通用项**（规范正文无对应元规则）；判定口径=命令 / 版本与现行生态一致。

**检查项**：
- 命令 / 工具链用法是否过时
- 版本号是否已 EOL 或与现行生态矛盾（版本本身应走默认值声明文件）
- 工具行为断言是否与当前版本一致（可 `webfetch` 核实，核不了标「未验证」）

**判定**：过时 / 矛盾 → 不合规，给「文件:行」与核实来源；核不了按事实纪律标注。

## 报告口径

报告为只读结论，按以下结构依次输出：

1. **一行结论**：确定性脚本结果 + 八维度通过计数 + 确证 / 待确认 / 通用项计数。
2. **八维度判定板**：每维度一行，列为 `维度 | 确定性 | 语义 finding | 判定态`。
3. **确证问题区**：确定性失败与 `语义·明确` 的 finding，逐条 `维度 / 文件:行 / 事实 / 依据(规范文件+条款) / 证据强度`。
4. **待人工确认区**：`语义·存疑` 与 `未验证` 的 finding，逐条附存疑理由。
5. **信息·通用项区**：非不合规的信息性通用项（如 ② 可达性），显式标注「非不合规」。

### 判定态词表（维度结论）

| 判定态 | 含义 |
|--------|------|
| 通过 | 该维度无任何 finding |
| 不通过 | 存在至少一个确证问题 |
| 待确认 | 无确证，但存在 `语义·存疑` |
| 未验证 | 无确证，且存在 `未验证` 项 |
| 不适用 | 该维度对本规范体系无检查项 |

维度判定态按固定 rollup 规则派生，不掺主观排序：

| 条件 | 判定态 |
|------|--------|
| 存在确定性失败 或 `语义·明确` | 不通过 |
| 无确证 且 存在 `语义·存疑` | 待确认 |
| 无确证 且 存在 `未验证` | 未验证 |
| 其余（可含通用项） | 通过 |
| 该维度无适用检查 | 不适用 |

每个维度在判定板输出且仅输出一行判定态，即便结论为「通过」。

### 证据强度词表（每条 finding）

| 证据强度 | 含义 |
|----------|------|
| 确定性 | 脚本判定 |
| 语义·明确 | 依据直接覆盖该情形，无需延伸解释（依据为规范条款，或规范正文无对应元规则时的已声明通用项口径） |
| 语义·存疑 | 判定依赖对规范的延伸解释，或规范对该情形无明文 |
| 未验证 | 依赖外部事实、无法核实 |

**确证问题区准入**：仅当 finding 能引一条直接覆盖该情形的依据、无需延伸解释时，方可入确证问题区。依据优先为规范条款；规范正文无对应元规则时（④ 内部一致性、⑧ 时效性），依据为审计方法已声明的通用项口径（见对应维度）。否则入待人工确认区并附存疑理由。不得将 `语义·存疑` 项列入确证问题区；不得将非不合规的信息性通用项表述为不合规。

### 边界声明

判定态是**合规状态枚举**、证据强度是**证据属性**，二者均非严重度 / 优先级分级，不违反规范体系「不引入严重度分级」的元规则。审计不引入规范外标准或严重度 / 优先级分级，不发明规范未给出的豁免；修改由人决策。确定性项可提示「重跑规范体系自带的一致性校验脚本」确认。

判定依据一律引自规范正文（`AGENTS.md` §六 与 `AGENTS-*.md` 相应条款），不引 openspec 内部 spec。
