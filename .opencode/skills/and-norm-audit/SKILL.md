# and-norm-audit 规范体系自审计

本 skill 对 `AGENTS-*.md` 规范体系做**八维度只读审计**：确定性项由脚本检查、语义项由 AI 判定，输出可按维度定位的问题清单，供人工决策。判定依据**规范体系既有元规则**，不发明规范外标准。

**本 skill 目录**：即本 `SKILL.md` 所在目录；`references/` 在此目录下。

**判定权威源**：`references/audit-dimensions.md`（八维度判定细则）+ 规范体系自身元规则（`./AGENTS.md` §六 与 `AGENTS-*.md` 相应条款）。

## 层级与范围

- **层级**：规范（权威，标准的唯一来源）→ 本 skill（**工具**，运行时读规范、只读）→ 规范文件（审计对象）。本 skill 引用规范 = 工具读标准，**非平级互依**。
- **范围**：本 skill 只做**合规审计**——审规范文件是否符合规范元规则；**不判断元规则本身的合理性**（元规则层评审属人工 / 外部，不在本 skill 范围）。
- **依据**：判定依据一律引自**规范正文**（`AGENTS.md` §六、`AGENTS-*.md` 条款），不引 openspec 内部 spec。

## 适用范围

- 审计对象为**规范体系自身**：`AGENTS-*.md` 与 `agents-defaults.yaml`
- 用户**手动触发**，输入为规范体系所在目录
- **只读不自动修**：只报告问题，不修改规范文件或配置
- **边界**：不审项目设计文档（`and-design-system-audit`）、不审代码 vs 设计（`and-implementation-audit`）、不审 change 上游（`and-openspec-upstream-audit`）、不校验技术文章（`and-validate-article`）

## 八维度（权威源：references/audit-dimensions.md）

| 维度 | 内容 | 类型 |
|------|------|------|
| ① 归属与加载 | 文件声明层 vs 路由表 / 加载表 / "不加载"列表 | 确定性 + 语义 |
| ② 交叉引用 | 目标存在 / 章节锚（§六.4）；单向 / 环（§六.7）；可达（通用项） | 确定性 + 语义 |
| ③ 边界与重复 | 同主题多文件重复定义、边界不清 | 语义 |
| ④ 内部一致性 | 文件内自相矛盾 | 语义 |
| ⑤ 可执行性 / 正确性 | 规则能否执行、误伤 / 漏判、含事实纪律（无出处断言） | 语义 |
| ⑥ 元数据 | 最后更新 / 版本齐全、无重复行 | 确定性 |
| ⑦ 语言政策 | 中英夹杂、模态标记统一 | 确定性 |
| ⑧ 时效性 | 命令 / 工具链 / 版本过时或矛盾 | 语义 |

报告形态（判定板 + 三分区）、判定态与证据强度词表见 `references/audit-dimensions.md` 的「报告口径」。

## 工作流

### Step 0：定位与输入

1. 输入为规范体系所在项目（含根 `AGENTS.md` 的项目根）；**读根 `AGENTS.md` 路由表（§二 层归属表）**，经其声明的路径定位各 `AGENTS-*.md` 与 `agents-defaults.yaml`（如 `norms/AGENTS-x.md`、`norms/agents-defaults.yaml`）；不假设规范文件与根 `AGENTS.md` 同目录
2. 读取元规则（根 `AGENTS.md` §六）与相关主 spec，作为判定依据

### Step 1：确定性检查（脚本）

运行**运行时发现的**规范体系自带一致性校验脚本（**用绝对路径**；脚本路径由规范体系自身确定，不写死），得到确定性维度的机器结果（① 层归属、② 引用目标存在与章节锚、⑥ 元数据、⑦ 中英夹杂/模态）。脚本失败项即确定性问题。

### Step 2：语义检查（AI，逐维度）

按 `references/audit-dimensions.md` 逐维度做 AI 判定，覆盖脚本未覆盖的语义项（③④⑤⑧ 及 ② 的单向/环语义、① 的加载语义）。每条判定**必引规范依据（文件 + 条款）**，允许人工覆核。

### Step 3：只读报告

按 `references/audit-dimensions.md` 的「报告口径」输出：

- **一行结论** + **八维度判定板**（每维度一行判定态：`通过` / `不通过` / `待确认` / `未验证` / `不适用`）
- finding 分三区：**确证问题区**（确定性失败与 `语义·明确`）、**待人工确认区**（`语义·存疑` 与 `未验证`）、**信息·通用项区**（非不合规的信息性通用项，标「非不合规」）

每条 finding：

```
维度 / 文件:行 / 事实 / 依据(规范文件+条款) / 证据强度(确定性/语义·明确/语义·存疑/未验证)
```

确证问题区只收能引一条直接覆盖依据的项：依据优先为规范条款，规范正文无对应元规则时（④ 内部一致性、⑧ 时效性）为审计方法已声明的通用项口径；拿不准的入待人工确认区。信息·通用项区只收非不合规的信息性通用项（如 ② 可达）。报告**只读**，不自动修改任何文件。

判定态（合规状态枚举）与证据强度（证据属性）**均非严重度 / 优先级分级**；审计**不引入规范外标准或严重度 / 优先级分级，不发明规范外豁免**。修改由人决策。

## 修复模式

**永远只报告**：不自动改规范文件或配置。确定性项可提示"重跑脚本确认"，语义项给「事实 + 依据 + 涉及位置」，具体怎么修由人决定。

## 输出语言

报告面向用户，使用简体中文；技术术语（AGENTS、openspec、markdown 等）与代码标识符保留英文。面向人阅读的内容（报告正文、维度名、问题描述）用简体中文；机器字段（路径、CLI flags）保留英文。
