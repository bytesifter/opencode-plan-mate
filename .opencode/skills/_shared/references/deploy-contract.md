# 部署驱动契约（共享权威）

本文件是 `and-*` 运维类 skill 驱动**集群 / 部署**操作的**单一权威**：定义「哪些动作必须经项目部署入口、哪些可直接访问」。`and-verify` / `and-integrate` / `and-local-governance` 以指针引用本文件，不复述正文。

## 一、规则

`[必须]` 运维**变更类**动作——**集群部署 / 应用部署 / 应用升级**——`[必须]` 经**项目声明的部署入口**（如项目提供的环境配置 + 部署编排命令）。

`[禁止]` skill 直接**变更**集群（如直接调用 `kubectl` / `helm` / 集群 API 执行部署、升级、删除等变更操作）。

`[必须]` **测试验证类**访问——读集群状态 / 探针 / 日志等**只读**访问——可**直接访问**，不受上述约束。

> 分界线是「变更 vs 读」，不是「集群 vs 应用」：变更一律经入口，读可直连。

## 二、为何经入口

- **命名空间隔离**：部署按「每 worktree / 分支一个命名空间」隔离（`ns = <项目前缀>-<seed>`）；入口负责合成 `ns`。任何绕过入口的**变更**都会落到错误的 / 共享的命名空间，破坏隔离。
- **单一变更点**：集群变更集中在一处，便于审计与回收。

## 三、seed 与命名空间

`[必须]` 驱动部署入口时 `[必须]` 传**部署 seed**（如当前分支名剥 `feature/`；master 集成验证用 `master`）。

`[必须]` 部署命名空间 `ns = <项目前缀>-<seed>`：**前缀属项目部署配置、由部署入口合成**；skill `[禁止]` 读取或拼接前缀，只提供 seed。

> 具体传参形态（`seed` 入参 / `--ns` 语义 / env 变量）由**项目部署入口**声明；本契约只约束「传 seed」的意图，不绑定具体项目实现。

## 四、ns 回收

`[必须]` 分支退役时 `[必须]` 回收其派生 namespace（`clean` 类入口，seed = 该分支）：

- **主**：`and-integrate` 合并该分支时回收（分支生命终点）。
- **兜底**：`and-local-governance` 清理该分支 / 其 worktree 时回收（防漏）。

## 五、无部署入口时

`[必须]` 项目未声明部署入口时，按调用方标准处理：`[必须]` 停下报告**或**记为「不适用 / 未执行」并记原因；`[禁止]` 臆断部署方式，`[禁止]` 以直接操作集群替代。
