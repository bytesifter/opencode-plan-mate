# 集成收口报告模板（and-integrate）

本模板定义**集成收口报告**的结构（合并 / 归档 / 收口提交与发布 / 未合并原因），供 `and-integrate` 每次收口落盘使用。报告写入 `<master worktree>/dev-notes/governance/<YYYYmmdd-HHMMSS>.md`。

```markdown
# 集成收口报告 <时间戳>

- 时间：<YYYY-mm-dd HH:MM:SS>
- 应用：<projectID>
- 执行入口：<master worktree 目录>
- 集成标准版本：<references/integration-standards.md 版本>

## 合并门禁与合并

| 分支 | change | 档位 | 门禁结果 | 合并结果 | 推送 |
|------|--------|------|---------|---------|------|
| <branch> | <change> | 1/2 | 过 / 未过(<reasons>) | 已合并(--no-ff) / 未合并 / 冲突停 | 成功 / 失败(原因) |

- 门禁判据：档位分治 + G3 测试完整性（计划承诺 → 报告兑现），由 `worktree_merge_check.py` 确定性输出 + AI 层语义判定。
- 门禁未过 → 不合并，原因记入「未合并（原因）」。

## 变更归档

| change | 合并门禁(档位) | 归档结果 | spec 合并 | 随 master 提交入库 |
|--------|--------------|----------|-----------|--------------------|
| <change 名> | 过(档位 1/2) / 未过(<未过项>) | 已归档 / 失败(<错误>) | 已合并进主 spec | 是 / 否(原因) |

- 归档先于收口提交执行；归档产物随收口提交（**仅本次产物路径**）入库。`openspec archive` 报错 → 记「异常」，停下。

## master 收口提交与发布

| 目录 | commit message | 推送 | 备注 |
|------|----------------|------|------|
| <master worktree> | integrate: <关联 change 主题> master 收口 | 成功 / 失败(原因) | 报告先落盘随提交入库；hash 由 git log 提供，不写入报告 |

- 收口判定：提交仅限**本次运行产物**（归档产物 + 集成报告）；HEAD 领先 `origin/master` → 发布；两者解耦，in-progress change 不门控。

## 未合并（原因）

| 分支 | change | 档位 | 未合并原因 |
|------|--------|------|-----------|
| <branch> | <change> | 1/2 | <测试计划/报告缺失 / 有失败 / 任务未勾完 / change 未完成（in-progress）/ 文档豁免失效 / config 不一致> |

## 异常

| 停止点 | 原因 |
|--------|------|
| <门禁/合并/归档/收口提交与发布> | <git 失败 / 合并冲突 / 归档报错 / 标准缺失 / 显式中断> |
```

## 填写规则

- **合并**：门禁通过的 `pending_merge` 对象一行，记录门禁结果与合并/推送。
- **归档**：`archives` 中 `archive_ready` 的 change 一行，如实记录；报错 → 「异常」。
- **收口提交与发布**：master 提交 / 发布结果；未执行记原因。
- **未合并（原因）**：只列门禁拦下的质量类原因（`reasons` 多项）。
- 报告 SHALL 独立于被删除的会话存在。
